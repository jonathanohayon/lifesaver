LIFE.SAVER v0.7.0 — Phase 13.8 Send Result Logs

Purpose:
Store clear, safe result-log records for support reply send outcomes.

Roadmap requirement:
- external message ID
- thread ID
- sent timestamp
- API response summary
- failure reason

Implementation:
- Added support send result logs module.
- Added result-log preview/status/example endpoints.
- Integrated the Gmail support send executor success and failure result paths with the result-log builder.
- Continued using the existing action_results table shape; no database migration required.

Safety:
- Result-log preview endpoints do not call Gmail.
- Result-log preview endpoints do not send email.
- No auto-send enabled.
- No bulk sending enabled.
- Manual approval remains required for real support sends.
- SUPPORT_SEND_EXECUTOR_ENABLED remains default-off.
- Raw OAuth tokens, raw MIME/base64, raw provider payloads, and raw Gmail response bodies are not returned to the browser.
- Failed sends are logged as failed and not claimed as sent.

Tests:
- npm run phase13:support-send-result-logs:test
- npm run phase13:support-sensitive-ticket-guard:test
- npm run phase13:support-send-executor:test
- npm run build
