LIFE.SAVER V2 — Phase 4.4 Status Filters
Version: v0.6.0
Deliverable: Filterable action queue

================================================================================
PURPOSE
================================================================================

Phase 4.4 adds a read-only status filter layer to the Actions approval queue UI.

The founder can now filter workspace-scoped actions by these primary statuses:

- Proposed
- Approved
- Rejected
- Executed
- Failed
- Cancelled
- Rolled Back

An All filter is also available.

This phase does not approve, reject, cancel, queue, execute, publish, send, spend,
pause, refund, rollback, or write to any external system.

================================================================================
UI DECISION
================================================================================

Primary action review page:
- actions.html

New UI added:
- Primary status filter tabs above the advanced filter toolbar.
- Active status filter summary card.
- Read-only helper text explaining the selected filter.
- Existing advanced dropdown remains available for full lifecycle statuses such as
  approval_required, auto_approved, queued, executing, and rollback_requested.

================================================================================
PRIMARY FILTERS
================================================================================

All:
Shows all workspace-scoped actions.

Proposed:
Shows actions waiting for review.

Approved:
Shows internally approved actions. Execution remains disabled until later executor
phases.

Rejected:
Shows actions rejected by an owner/admin.

Executed:
Future status for actions confirmed by executor result. No executor is enabled in
this phase.

Failed:
Future status for failed execution or lifecycle result review.

Cancelled:
Shows actions cancelled before execution.

Rolled Back:
Future status for actions with confirmed rollback completion after rollback flow exists.

================================================================================
SAFETY RULES
================================================================================

1. Status filters are read-only UI controls.
2. Changing a filter may only call GET /api/v1/actions with safe query parameters.
3. Status filters must never call approve, reject, cancel, queue, execute, rollback,
   publish, send, spend, pause, refund, or edit endpoints.
4. List view remains summary-only.
5. Full raw payload_json is not exposed in the list view.
6. Detail drawer continues to show only safe payload preview.
7. No external write connector is enabled in Phase 4.4.
