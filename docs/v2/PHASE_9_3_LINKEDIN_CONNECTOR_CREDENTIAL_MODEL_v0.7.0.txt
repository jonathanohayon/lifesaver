================================================================================
TOKEN STORAGE RULE
================================================================================

Raw access/refresh tokens may exist only briefly inside backend memory during a future OAuth callback.

Raw tokens must never be:
- returned to the browser,
- logged,
- saved in docs,
- saved in action payloads,
- saved in result logs,
- displayed in admin UI.

Only encrypted values are persisted.

================================================================================
BROWSER-SAFE STATUS RESPONSE
================================================================================

Browser may see:
- provider
- connection kind
- status
- connected boolean
- account hint
- granted scopes
- expiry timestamps
- last connected/disconnected timestamps
- safe metadata

Browser must not see:
- access token
- refresh token
- encrypted access token
- encrypted refresh token
- token fingerprint
- raw LinkedIn member URN if sensitive

================================================================================
DISCONNECT BEHAVIOR
================================================================================

Disconnect does:
- clears encrypted access token,
- clears encrypted refresh token,
- clears token fingerprint,
- marks status disconnected,
- records who disconnected,
- records disconnected_at,
- logs a safe system event.

Disconnect does not:
- call LinkedIn revoke API yet,
- publish content,
- delete LinkedIn posts,
- modify any external account.

External revoke planning can be added later when LinkedIn OAuth routes and API client exist.
