================================================================================
PURPOSE
================================================================================

Phase 5.2 defines and implements the backend meaning of pause_all_autonomy.

When pause_all_autonomy is true for a workspace:

1. No auto-approval is allowed.
2. No executor execution is allowed.
3. Existing proposed actions remain reviewable.
4. Safe new proposed actions may still be created for founder review.

This is the backend interpretation layer for the future Master Pause Switch. It does not add
the pause/resume API or UI yet.

================================================================================
BACKEND BEHAVIOR
================================================================================

The new autonomy service reads the workspace autonomy_settings row.

If the row is missing, the service creates a default row with:

pause_all_autonomy=false
pause_content_actions=false
pause_support_actions=false
pause_ads_actions=false
updated_by=null
updated_at=now()

This keeps future code from failing when a workspace has no autonomy settings row yet.

================================================================================
CREATE PROPOSED ACTION BEHAVIOR
================================================================================

createProposedAction now checks the global pause state.

If pause_all_autonomy is false:
- the action may be created normally,
- but still remains internal and non-executing.

If pause_all_autonomy is true:
- the action may still be created if it passes normal validation,
- approval_required is forced to true,
- policy_decision is forced to ask,
- audit metadata records that global pause was active,
- no auto-approval is allowed,
- no executor execution is allowed.

This matches the Phase 5.2 rule:
Existing proposed actions remain reviewable, and safe new proposed actions may still be created.
