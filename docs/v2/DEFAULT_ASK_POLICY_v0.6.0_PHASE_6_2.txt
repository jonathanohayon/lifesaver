LIFE.SAVER V2 — PHASE 6.2 DEFAULT ASK POLICY
Version: v0.6.0
Phase: 6.2
Deliverable: Default ask behavior

================================================================================
PURPOSE
================================================================================

Phase 6.2 defines the safest fallback behavior for the future policy/rules engine.

Rule:
If no enabled policy rule matches an action, LIFE.SAVER must return ask/manual review.

This protects the founder from accidental autonomy.

================================================================================
DEFAULT ASK RULE
================================================================================

When a proposed action enters policy evaluation:

1. If an explicit enabled policy rule matches:
   - The matched rule decision may continue to later safety checks.
   - Possible matched decisions: ask, auto_approve, block.

2. If no enabled policy rule matches:
   - Effective decision must be ask.
   - approval_required must be true.
   - autoApprovalAllowed must be false.
   - executorExecutionAllowed must be false.

3. If caller/tool requests auto_approve without a matched rule:
   - LIFE.SAVER forces ask.
   - The caller cannot self-authorize autonomy.

================================================================================
WHY THIS MATTERS
================================================================================

V2 will eventually allow LIFE.SAVER to act as an operator. That means policy decisions
must be conservative by default.

Without this rule, a bug, tool, worker, or prompt mistake could accidentally create an
auto-approved action even when the founder did not create a rule allowing it.

Default ask makes the safe path simple:

No rule = ask the founder.
