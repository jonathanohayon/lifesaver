LIFE.SAVER V2 — EXECUTOR PAUSE ENFORCEMENT
Version: v0.6.0
Phase: 5.6 — Executor Enforcement
Status: Backend safety foundation only

================================================================================
PURPOSE
================================================================================

Phase 5.6 creates the required backend pause guard contract for every future executor.

The rule is non-negotiable:

- Every executor must check pause state immediately before execution.
- If pause_all_autonomy is true, execution is blocked even if the action was approved earlier.
- If a matching category pause is true, execution is blocked for that category.
- If pause state cannot be read, execution must fail closed.

This phase does not register any executor and does not execute anything.

================================================================================
CORE FUNCTIONS
================================================================================

evaluateExecutorPauseState(intent)
- Reads workspace autonomy settings.
- Maps action_type to autonomy category.
- Returns whether execution is blocked.
- Does not execute anything.

assertExecutorNotPaused(intent)
- Calls evaluateExecutorPauseState().
- Throws AUTONOMY_EXECUTION_PAUSED if global/category pause blocks execution.
- This is the function future executors must call immediately before execution.

runWithExecutorPauseGuard(input, executor)
- Wrapper pattern for future executor phases.
- Runs the pause guard first.
- Runs the provided executor only if pause guard allows continuation.
- In Phase 5.6, no real executors are registered.

listExecutorRegistrySafetyState()
- Confirms executor registry is intentionally disabled.
- Lists action types as not registered until future sandbox/real executor phases.

================================================================================
ENFORCEMENT RULES
================================================================================

Global pause:
- pause_all_autonomy = true blocks all future executor execution.
- Existing proposed/approved actions remain reviewable.
- Resuming pause does not automatically execute waiting actions.

Category pause:
- pause_content_actions blocks content_publish execution.
- pause_support_actions blocks support_reply_send execution.
- pause_ads_actions blocks ad_budget_adjust and ad_pause execution.
- pause_research_actions blocks research_task execution.
- pause_dev_actions blocks dev_task execution.

Fail-closed behavior:
- If DATABASE_URL is missing or pause state cannot be verified, executor execution is blocked.
- Future real executors must not run when pause state is unknown.
