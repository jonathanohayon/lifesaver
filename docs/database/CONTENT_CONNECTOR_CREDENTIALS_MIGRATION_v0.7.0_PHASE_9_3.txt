================================================================================
CONTENT CONNECTOR CREDENTIALS MIGRATION — v0.7.0 PHASE 9.3
================================================================================

Migration file:
`database/migrations/017_create_content_connector_credentials.sql`

Purpose:
Create a dedicated encrypted credential table for future content publishing connectors, starting with LinkedIn.

Why a new table instead of reusing Triple Whale connected_accounts:
Triple Whale currently stores a customer-owned read-only API key. LinkedIn content publishing will use OAuth credential material with different fields: access token, optional refresh token, scopes, token expiry, provider account hints, and disconnect history. A dedicated table keeps the content publishing security model clean and avoids risky changes to the existing Triple Whale connector.

Additive safety:
- Creates a new table.
- Creates indexes.
- Adds comments.
- Does not alter existing tables.
- Does not drop existing columns.
- Does not backfill existing production data.
- Does not rewrite encrypted Triple Whale keys.

Main table:
`content_connector_credentials`

Important fields:
- `workspace_id`: workspace ownership.
- `provider`: currently constrained to `linkedin`.
- `connection_kind`: currently member/organization, but Phase 9.3 uses member only.
- `provider_account_id_hash`: one-way hash of provider account identifier.
- `provider_account_hint`: safe browser display hint.
- `encrypted_access_token`: encrypted OAuth access token.
- `encrypted_refresh_token`: encrypted OAuth refresh token if available.
- `token_fingerprint`: one-way server-side fingerprint, not browser-facing.
- `granted_scopes_json`: granted OAuth scopes.
- `access_token_expires_at`: access-token expiry.
- `refresh_token_expires_at`: refresh-token expiry if available.
- `status`: connected/expired/disconnected/revoked/token_decrypt_failed/connection_error.

Security rules:
- Do not return `encrypted_access_token` to browser.
- Do not return `encrypted_refresh_token` to browser.
- Do not return `token_fingerprint` to browser.
- Do not log raw tokens.
- Do not place raw tokens in action payloads.
- Keep `APP_ENCRYPTION_KEY` stable.

Phase 9.3 safety status:
- Real publishing: not added.
- External API calls: not added.
- OAuth callback: not added.
- Auto-run: not enabled.
